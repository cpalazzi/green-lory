# Supported Helper Scripts

Only the scripts listed here are part of the supported human workflow.

## `fetch_travel_time.py`

Builds `data/travel_time_by_cell.csv` by querying the MAP/Oxford Accessibility to Cities 2015 dataset in Google Earth Engine for each onshore 1 degree cell in `data/max_capacities_paper_2pct_slope15.csv`.

Requirements:
- authenticated Google Earth Engine access
- `data/max_capacities_paper_2pct_slope15.csv` already generated by `notebooks/01_max_capacities.ipynb`

Typical usage:

```bash
python scripts/fetch_travel_time.py
```

## `build_ameli_wacc_inputs.py`

Builds Ameli et al. (2021) Fig. 2 WACC override CSVs after `notebooks/02_spatial_cost_inputs.ipynb` has generated a spatial base file.

Typical usage:

```bash
python scripts/build_ameli_wacc_inputs.py
```

Default outputs for the reduced-WACC case use the short token `amelired`:
- `inputs/amelired_wacc_tiam_regions_2050.csv`
- `inputs/amelired_wacc_country_map_2050.csv`
- `inputs/amelired_interest_inputs_2050.csv`
- `inputs/spatial_cost_inputs_amelired_2050.csv`

Use `inputs/spatial_cost_inputs_amelired_2050.csv` for
`spatial_build_remote_water_amelired` runs, where Ameli WACC is combined with
the active spatial build/remoteness/water mechanisms. The current land-cost
column is zero, so `land` should not appear in the run label for this file.
`inputs/amelired_interest_inputs_2050.csv` is the WACC-only input and should be
labelled as `flat_amelired` when used for an optimization run.

Important behavior:
- The WACC-only output covers the union of the spatial base grid and the optional `--locations-input` grid.
- When `--locations-input` is a max-capacity CSV, rows with `max_capacity_mw <= 0` are ignored because they are not active run locations.
- The combined output can only cover coordinates present in `--spatial-input`.
- If `--locations-input` contains extra cells, the script prints a warning and you should regenerate notebook 02 on the matching land grid before using the combined output for a full-spatial run.

## `merge_global_results.py`

Merges quadrant outputs such as `results/way-2050-spatial-east1/run_global_*.csv` into one canonical scenario CSV, deduplicates by `(latitude, longitude)`, and validates required land/paper-capacity columns.

Typical usage:

```bash
python scripts/merge_global_results.py way-2050-spatial-build-remote-water-paper-2pct-slope15 \
  --output results/way_2050_spatial_build_remote_water_paper_2pct_slope15/global_run_results_1h_2050.csv
```

Useful options:
- `--results-dir` to point at a different results root
- `--allow-missing-quadrants` to merge partial runs intentionally
- `--required-column` to enforce extra schema checks

## Policy

All other files under `scripts/` are treated as local diagnostics, scratch helpers, or Copilot convenience tools. They are intentionally excluded from the supported interface and remain gitignored.
